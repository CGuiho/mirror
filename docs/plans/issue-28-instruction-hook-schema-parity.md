# Issue 28 Instruction Hook Schema Parity Implementation Plan

## Decision-Sealed Summary

This is a bounded publication-parity bug. The accepted hook architecture and
production Go runtime already answer the product and technical questions:

- `pkg/config.JSONSchema()` is the authoritative schema generator;
- `mirror/schema/mirror.schema.json` is the checked-in artifact used by the
  raw URL that `mirror init` writes into new YAML files;
- canonical major events such as `after:plan` accept an object containing
  `instructions`, `commands`, or both;
- internal write/commit/tag/push events and compatibility aliases are command-
  only;
- the archived Bun/TypeScript implementation is historical evidence, not a
  second generator.

No human question remains for unattended execution. If the implementation
baseline contradicts any statement above, stop and return the plan to the SWE
Maestro instead of choosing a new hook contract.

### Execution

1. Change the task state from `todo` to `in progress`, refresh `Updated`, and
   create `docs/questions/issue-28-instruction-hook-schema-parity/S28-01.md`

4. Strengthen focused schema assertions so the generated schema explicitly
   proves the accepted contract rather than relying only on substring checks:
   - positive: `after:plan` and another major event expose string, non-empty
     string-list, and object alternatives;
   - positive: canonical major-event objects expose `instructions` and
     `commands`, each accepting one non-empty string or a non-empty list;
   - positive: internal events and compatibility aliases retain command string,
     list, and `{commands: ...}` compatibility;
   - negative schema contract: `additionalProperties: false`, closed event
     names, non-empty values, command-only internal events, and command-only
     aliases are encoded so unknown events/fields, empty values, internal
     instructions, and alias instructions cannot validate.
5. Refresh `mirror/schema/mirror.schema.json` mechanically with the exact
   output of the production Go generator plus one trailing newline. Do not copy
   or adapt the archived TypeBox schema.
6. Run focused tests and independently compare `go run . config schema` output
   to the committed file. Confirm a second generation produces no diff.

- `go test -count=1 ./pkg/config` passes.
- `go run . config schema` parsed as JSON contains explicit `after:plan`, three

- Exact bytes from `go run . config schema` equal
  `mirror/schema/mirror.schema.json` (accounting only for the command's single

- Re-running the generation procedure leaves the worktree unchanged.
- Runtime fixture: `go run . config check --config <disposable issue-28

- Schema fixtures or equivalent structural assertions cover these rejections:
  unknown event; unknown object field; `{}`; empty instruction string; empty
  instruction/command list; `before:commit.instructions`; and
  `before_apply.instructions`.

If validating instance documents against the JSON Schema would require adding
a new runtime dependency, do not add one by default. Use focused structural
contract assertions plus existing runtime negative fixtures. Record the
limitation for plan review if those checks cannot prove a required negative.

- Code rollback: revert the focused schema/test commit if it causes a false
  schema contract or CI regression; do not hand-edit only one side of the
  parity pair.
- Documentation rollback: revert only inaccurate task-owned metadata.
- Published-release rollback: no release exists in this plan. If a later
  authorized release publishes an incorrect schema, stop further promotion,
  preserve the tag/release evidence, correct on a new branch, and use a new
  Mirror-managed version; do not rewrite public tags.
- Primary risk: future generator changes without refreshing the artifact. The
  exact parity test is the required control.
- Secondary risk: a structural schema can diverge from runtime semantics. The
  positive/negative hook matrix plus runtime fixtures is the required control.
- Residual risk: editors may differ in draft support; the artifact declares
  JSON Schema 2020-12, and public raw-URL validation remains the post-merge
  evidence boundary.
